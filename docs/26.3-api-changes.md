# 26.2 → 26.3 API 变更（实测记录）

本文件记录本轮升级**实测核实**的 API 差异（对照 26.2 / 26.3 的 merged dev jar 用 `javap` 逐项确认），
供后续移植与 headless-jei/26.3 复用。26.3 是**大改动版本**，不是补丁版本。

版本基线：Minecraft 26.3（release，2026-09-15，Java 25）、Fabric Loader 0.19.5、
Fabric API 0.161.0+26.3、Cloth Config 26.3.158、Fabric Loom 1.17.18（**无需升级**）。

---

## 1. 窗口/输入：GLFW → SDL3（影响最大）

| 26.2 | 26.3 |
|---|---|
| `org.lwjgl:lwjgl-glfw` 在编译类路径上 | **整个 `org.lwjgl.glfw` 包消失**；改由 `org.lwjgl:lwjgl-sdl:3.4.3` 提供窗口 |
| `InputConstants`（`com.mojang.blaze3d.platform`） | 位置不变，但：`isKeyDown(Window, int)` → **`isKeyDown(int)`**；新增 `getKey(KeyEvent)` |
| `InputConstants.Type.KEYSYM` / `SCANCODE` | **只剩 `Type.KEYBOARD` / `Type.MOUSE`**（GLFW 的 keysym/scancode 区分被移除） |
| `KeyEvent.scancode()` | **`KeyEvent.keycode()`**（record 分量仍是 `key, keycode, modifiers`） |
| `GLFW.glfwCreateCursor` / `GLFWImage` | **无对应物**：只有 `CursorTypes`（标准光标）+ `Window.selectCursor(CursorType)`；`CursorType.createStandardCursor(int, String, CursorType)` 是唯一工厂 |

**BRBE 影响**：
- `ClientCompat`：`isKeyDown(window, k)` → `isKeyDown(k)`；`Type.KEYSYM` → `Type.KEYBOARD`。
- 所有 `event.scancode()` → `event.keycode()`（6 个文件 10 处）。
- `ViewerCursor`（读系统光标主题、栅格化 SVG/Xcursor、自造"抓取拳头"光标）**在 26.3 无公开 API 可实现**：
  LWJGL 的 SDL 绑定**不导出** `SDL_CreateColorCursor` / `SDL_CreateSurfaceFrom`（已核对 jar 内类清单），
  因此阶段 A 退化为返回 `null` → 调用方回退 `CursorTypes.RESIZE_ALL`（该类原本就有的降级路径）。
  若要恢复，需要 `java.lang.foreign` 直接 downcall libSDL3（后续可选）。

## 2. 渲染管线：`blaze3d.pipeline` → `renderpearl`

| 26.2 | 26.3 |
|---|---|
| `com.mojang.blaze3d.pipeline.RenderPipeline` | **`com.mojang.renderpearl.api.pipeline.RenderPipeline`** |
| `net.minecraft.client.renderer.RenderPipelines` | 包不变，但字段类型变为 renderpearl 版 |

`GuiGraphicsExtractor.blitSprite/blitNineSlicedSprite/blitTiledSprite` 的 pipeline 参数随之改类型 →
`brbe.common.accesswidener` 里 3 条 AW 描述的 `Lcom/mojang/blaze3d/pipeline/RenderPipeline;` 必须同步改。

## 3. Tooltip：`tooltip(...)` 末尾多一个 `boolean`

| 26.2 | 26.3 |
|---|---|
| `tooltip(Font, List<ClientTooltipComponent>, int, int, ClientTooltipPositioner, Identifier)` | **多一个尾部 `boolean`**（7 参）；`setTooltipForNextFrameInternal(...)` 由 private 变 **public** |

BRBE 4 处调用补 `false`（默认语义：不额外加行距）。
`setTooltipForNextFrame(...)` 家族另新增若干重载（含 `Identifier, boolean` 变体）。

## 4. 燃料与堆肥：表格 → 数据包 loot provider

26.3 删除了两张硬编码表，改为**物品组件 + `minecraft:context_int_provider` 数据包注册表**
（provider 用 `LootContext` 求值，客户端没有 `ServerLevel` 无法如实求值）：

| 26.2 | 26.3 |
|---|---|
| `FuelValues`（`Level.fuelValues()`） | 组件 `DataComponents.COOKING_FUEL`（`CookingFuel.burnTime(): ResolvableInt`） |
| `ComposterBlock.COMPOSTABLES`（Item → float 概率） | 组件 `DataComponents.COMPOSTABLE`（`Compostable.layers(): ResolvableInt`，"增加层数"） |
| `values.isFuel(stack)` / `values.fuelItems()` | 遍历 `BuiltInRegistries.ITEM` 按组件存在性判定 |

**堆肥语义变了**：不再是"概率"，而是 `ComposterBlock.addLayer(...)` 直接叠加的**层数**（7 层封顶，
且"堆肥桶 0 层时必定 +1"由 provider 的 `number_dispatcher` case 表达）。

**BRBE 的处理**：新增 `util/LootIntResolver`，在客户端对 provider 树做**结构化期望值**求解：
- `weighted_list` → 概率加权平均 —— vanilla 的 `compostable/low` 等正好还原出旧版数字
  （low=0.3、low_medium=0.5、medium=0.65、medium_high=0.85、always_add_one=1.0），
  所以 tooltip 仍显示原来的"概率：x%"；
- `number_dispatcher` → 取 `default` 分支（上下文 case 客户端无法判定）；
- `conditional` → 取 `on_false`（无快炊加成）—— 于是 `cooking/time_coal` = `1600 / 1` = **1600 ticks**，
  与旧版燃烧时长一致；
- 算术 provider（`+ - * /`、min/max/abs/negate）递归求值；无法解析 → 0（调用方降级为"未知"）。

## 5. `PotionBrewing` 整个被删（酿造改为常规配方）

| 26.2 | 26.3 |
|---|---|
| `net.minecraft.world.item.alchemy.PotionBrewing`（+ 包私有 `Mix` record，靠反射读） | **类不存在** |
| `Level.potionBrewing()` | **方法不存在** |
| — | 新增 `RecipeType.BREWING` / `BrewingRecipe` / `BrewingInput` / `PotionIngredient`；配方在 `data/minecraft/recipe/brewing/*.json`（289 条相关数据） |
| — | `Level.getRecipeManager()` **也不存在** → `Level.recipeAccess()`（`RecipeManager implements RecipeAccess`） |

**BRBE 影响**：`PlatformPotionUtilImpl` 重写为从配方管理器取 `BrewingRecipe`：
`getIngredient` ← `getReagent().ingredient()`；`getFrom` ← `getInput().potions()`（`PotionsPredicate.potions()`）；
`getTo` ← `getOutput().create()` 的 `POTION_CONTENTS` 组件。
配套删除 `FabricPotionBrewingAccessor`（mixin 目标类已不存在）及其 mixin 注册、
以及 AW 里 5 条 `PotionBrewing*` 描述（否则 AW 校验直接失败）。

## 6. 杂项

| 26.2 | 26.3 |
|---|---|
| `ContextMap.Builder` / `ContextKeySet.Builder`（可构造空上下文） | 均为 private，**`ContextMap.EMPTY`** 是唯一公开空实例 |
| `SlotDisplay.TagSlotDisplay(TagKey<Item>)` | **收 `HolderSet<Item>`**（用 `BuiltInRegistries.ITEM.get(tagKey)` 取） |
| `ComposterBlock.COMPOSTABLES` | 见 §4 |
| 真实 JEI | 30.24.0.165 → **31.3.0.17**（fabric，跨大版本） |

## 7. 26.3 对 JEI 生态的连带变化（headless fork 相关）

| 26.2 fork | 26.3 变化 |
|---|---|
| JEI 源码覆盖 api/common/library/gui/fabric（865 文件，834 个与官方一致） | 基线改为**官方 JEI 26.3 源码**，同清单取文件；模块重组：CommonApi/FabricApi 并入 `Common`，`gui/input`→`common/input`、`gui/GuiProperties`→`common/gui`、`common/search.SearchMode`→`common/config`、`network/packets`→`packets/legacy` |
| JEI 自带 TOML 配置系统（`common/config/file/**`、`ConfigManager`、`JeiClientConfigs`） | **整体删除**，改为独立 mod **`mezz_config` 0.6.3**（`net.mezzdev.config:mezz_config-26.3-config-api:0.6.3`，API 在 `net.mezzdev.config.api.**`）；官方 JEI 也是 jar-in-jar 内嵌它并 `depends` |
| `JeiAtlasManager` / `Textures.getAtlasManager()` | **删除**：MC 26.3 自带 `AtlasManager`，JEI 直接 `Minecraft.getAtlasManager().getAtlasOrThrow(AtlasIds.GUI)` —— BRBE 里"注册 JEI atlas"的 mixin 因此成为空操作 |
| `CycleTicker`/`CycleTimer` 用 GLFW 直接读键 | 官方改用 `InputConstants`；fork 的 Alt 暂停语义照旧（`manualIndexOverride` 保留） |
| `StartData(plugins, serverConnection)` | 新增第三组件 `JeiConfigData`（经 `JeiConfigRegistration.register()` 构建，内部会 `Internal.setClientConfigs(...)`） |
| `RecipeMap.create(Collection<RecipeHolder<?>>)` | **`RecipeMap.create(HolderLookup<Recipe<?>>)`** —— 改由配方注册表 lookup 构建（官方 `VanillaClientRecipeLoader` 同路径） |
| `IInternalKeyMappings` / `IGuiHelper` / `IRecipeSlotBuilder` / `IRecipeCatalystRegistration` | 各新增抽象方法：`getConfigKeyMappings()`、`createRecipeSlotDrawable(...)`×2、`createDrawableIngredient(IIngredientRenderer<V>, V)`、`setPosition(区域对齐六参)`、`addCraftingStation(IRecipeType<?>, SlotDisplay)` |
| 键位接口 | `getBookmark()/getShowRecipe()/getShowUses()` 返回类型收紧为 `IJeiKeyMappingWithExtraModifiers` |

⚠️ **dev 运行陷阱**：Fabric Loader **不会**在 dev（`runClient`）下展开 jar-in-jar —— 内嵌 jar 提供的
入口点会 `ClassNotFoundException`。主 mod 因此额外用 `runtimeOnly` 把 headless-jei 与 mezz_config
挂到 dev 运行时（成品 jar 只走 `fabric.mod.json` 的 `jars`）。

## 8. 本轮未踩到但需留意

- 26.3 的 `GuiGraphicsExtractor` 新增若干 tooltip 重载（`Identifier, boolean` / `Component, int, int, Identifier`），
  后续调用注意重载歧义。
- `RecipeBookComponent.selectMatchingRecipes` 在 26.2/26.3 **都是两个重载**（private 无参 + protected 抽象两参），
  BRBE 的 `@Inject(method = "selectMatchingRecipes")` 两分支写法一致 —— 不是 26.3 的新问题。
- `Libs/jei-26.3-fabric-31.3.0.17.jar` 目前仅作 **compileOnly** 编译参考（阶段 A）；
  阶段 B 换回 `headless-jei-fabric-26.3-1.0.0.jar` 并恢复 jar-in-jar 内嵌。
