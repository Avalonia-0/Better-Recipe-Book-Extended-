# 26.3 LEI 预览"黑紫纹理"：headless JEI 的贴图目录与官方 26.3 不一致

## 症状

用户实测：LEI 查询界面的**预览**（Shift 弹窗 / tooltip 内嵌预览）"无法调用 JEI 界面"，
显示成黑紫（missing texture）格子。

## 根因

26.3 的 JEI 精灵（sprite）解析路径是**原版 GUI 图集**：

```java
// mezz/jei/common/Internal.java（我们的 fork 与官方逐字节一致）
TextureAtlas guiAtlas = minecraft.getAtlasManager().getAtlasOrThrow(AtlasIds.GUI);  // minecraft:gui
// mezz/jei/common/gui/textures/Textures.java
private Identifier createSpriteId(String name) {
    return Identifier.fromNamespaceAndPath(ModIds.JEI_ID, name);   // → jei:<name>
}
```

即 sprite id 是 `jei:slot` / `jei:recipe_preview_background` 这类，**要求贴图文件位于
`assets/jei/textures/gui/sprites/**`**（原版 `minecraft:gui` 图集的 `directory` source 扫的是
所有命名空间的 `textures/gui/sprites`，前缀为空，于是文件 → id 正好是 `jei:<相对路径>`）。
官方 JEI 26.3 的 gametest 就是这么断言的：
`Identifier.fromNamespaceAndPath("jei","slot")` 必须能在 GUI 图集里取到。

而我们的 headless fork 里装的是 **26.2 时代的旧布局**：

```
assets/jei/atlases/gui.json                     ← 自己定义了一个 jei:gui 图集
assets/jei/textures/jei/atlas/gui/slot.png      ← 贴图在这个自定义图集目录下
```

两个致命点：

1. **那份 `atlases/gui.json` 根本不会被读**。26.3 的图集定义是
   `SpriteSourceList.load(rm, definitionLocation)` → `FileToIdConverter.idToFile(minecraft:gui)`
   → 只读 `assets/minecraft/atlases/gui.json`（`AtlasManager.KNOWN_ATLASES` 是写死的 12 个图集，
   每个带一个 `definitionLocation`）；mod 自己的 `assets/<ns>/atlases/gui.json` 不在读取路径上。
2. 于是贴图**从未被缝合进 `minecraft:gui`**，`atlas.getSprite(jei:slot)` 返回 missing sprite
   （黑紫）。而且旧布局还缺官方后来新增的 3 张图
   （`button_disabled`、`button_enabled`、`button_highlight`、`icons/tag_badge`、`icons/list_badge`、
   `interactive_ingredient_tooltip_background` —— 代码已经在引用）。

## 修复

把 fork 的资源树整体换成**官方 JEI 26.3 的**（`SourceCode/JustEnoughItems-26.3/Common/src/main/resources/assets/jei`）：

```bash
cd headless-jei/26.3/src/main/resources
rm -rf assets/jei
cp -r <official>/Common/src/main/resources/assets/jei assets/
cp <official>/Common/src/main/resources/jei-icon.png .
```

- 删掉死掉的 `assets/jei/atlases/gui.json`；
- 贴图落在 `assets/jei/textures/gui/sprites/**`（51 张，含 20 个 9-slice/nine_slice 元数据）；
- 语言文件同步到官方版本（旧的也是过期快照）。

重建 fork → 覆盖 `26.3/libs/headless-jei-fabric-26.3-1.0.0.jar`（编译参考 + dev 运行时）与
`26.3/src/main/resources/META-INF/jars/headless-jei-fabric-26.3-1.0.0.jar`（成品内嵌）→ 重建主 mod。

## 验证

探针在游戏内向 GUI 图集查 sprite（等价官方 gametest 的断言）：

```
gui_atlas_textures: jei:slot=OK jei:icons/flame=OK jei:recipe_preview_background=OK
                    jei:single_recipe_background=OK jei:gui_background=OK
                    brbe:recipe_book/column_panel=OK
```

修复前同一断言为 `MISSING`（见 `26.3-jei-preview-before.png` / `-after.png`：前者预览是黑紫格，
后者是正常的合成配方预览）。

## 备忘

- **26.3 的 GUI 精灵一律放 `assets/<modid>/textures/gui/sprites/**`，id = `<modid>:<相对路径>`；
  想让精灵进别的图集，只能往 `assets/minecraft/atlases/<atlas>.json` 里加 source（原版那份文件）。**
- 内置资源包覆盖 9-slice 贴图时必须连 `.mcmeta` 一起放（见根级 CLAUDE.md 的
  "column_panel 缺 mcmeta" 记录）——同一个"元数据/定义不跨来源回退"的规则。
