# 26.1.2 → 26.2 Migration Plan

## 总体目标
在 26.2 分支上实现 26.1.2 的所有功能，并解除对 Architectury API 的依赖。

## Phase 0: 分支准备 (已完成或立刻执行)

### Step 0.1: 创建 26.2 分支
```bash
git checkout 26.1.2
git checkout -b 26.2
```

### Step 0.2: 防止分支污染
- `build.gradle` 已有分支-版本一致性检查（branch name == minecraft_version）
- `gradle.properties` 中设置 `minecraft_version=26.2`
- `.gitignore` 确保 `libs/`、`.gradle/`、`build/` 被排除

## Phase 1: 依赖版本更新

### 1.1 Minecraft 版本
当前 26.1.2 → 目标 26.2（使用 26.2-rc-2 或 26.2 正式版）

### 1.2 核心依赖版本
| 组件 | 26.1.2 版本 | 26.2 目标版本 | 备注 |
|------|------------|-------------|------|
| Minecraft | 26.1.2 | 26.2 | Mojang version manifest 中可用 (rc-2) |
| Fabric Loader | 0.19.2 | 0.19.3+ | 可能需要更新 |
| Fabric API | 0.150.0+26.1.2 | 待确认 26.2 对应版本 | 需查 Maven |
| NeoForge | 26.1.2.71 | 待确认 26.2 对应版本 | 需查 Maven |

| ModMenu | 17.0.0-beta.2 | 待确认 | Fabric only |
| **architectury-fabric** | 20.0.4 | **移除** | 见 Phase 2 |

- 移除 `architectury-plugin` 
- 移除 `dev.architectury.loom-no-remap`

- 或者保留 `dev.architectury.loom-no-remap` 只用于构建（不用其 API）

## Phase 2: 移除 Architectury API 依赖

### 2.1 受影响的 API 及替换方案

#### KeyMappingRegistry
- **原作地点**: `BetterRecipeBook.java:4`
- **用途**: 注册 3 个按键绑定 (PIN_MAPPING, RECIPE_VIEW_MAPPING, USAGE_VIEW_MAPPING)
- **替换方案**:
  - Fabric: `net.fabricmc.fabric.api.client.keybinding.v1.KeyBindingHelper.registerKeyBinding()`
  - NeoForge: `net.neoforged.neoforge.client.event.RegisterKeyMappingsEvent`
  - common 中定义接口 `PlatformKeyMapping`，fabric/neoforge 各自实现

#### Platform.isModLoaded() / Platform.getMod()
- **原作地点**: `CompatMixinPlugin.java`, `ReiCompat.java`, `ModNameUtil.java`
- **替换方案**:
  - Fabric: `net.fabricmc.loader.api.FabricLoader.getInstance().isModLoaded(id)` / `getModContainer(id).getMetadata().getName()`
  - NeoForge: `net.neoforged.fml.ModList.get().isLoaded(id)` / `getModContainerById(id).getModInfo().getDisplayName()`
  - common 中定义接口 `PlatformHelper`，fabric/neoforge 各自实现

#### 事件系统 (ClientLifecycleEvent, LifecycleEvent, ClientGuiEvent, ClientTickEvent)
- **原作地点**: `PotionLoader.java` (common), `BetterRecipeBookClientNeoForge.java`
- **用途**: 客户端生命周期、GUI 初始化、客户端 tick、渲染事件
- **替换方案**:
  - Fabric: 使用 Fabric API 事件 (`ClientTickEvents`, `ScreenEvents`, `ClientLifecycleEvents` 等)
  - NeoForge: 使用 NeoForge 事件总线 (`RenderGuiEvent`, `ClientTickEvent`, `ScreenEvent.Init` 等)
  - common 中定义事件接口，各平台实现
  - 或者：将事件注册移到各平台的 entry point 中（Fabric 已经在 `BetterRecipeBookClientFabric` 中直接使用 Fabric API）

**关键洞察**：Fabric 端的 `BetterRecipeBookClientFabric` **已经**直接使用 Fabric API 事件（不用 Architectury）。只有 NeoForge 端和 common 中的 `PotionLoader` 还在用。我们可以让 NeoForge 也用原生事件，消除依赖。

### 2.2 具体替换清单

| 文件 | 当前 API | 替换为 |
|------|---------|--------|
| `BetterRecipeBook.java` | `KeyMappingRegistry` | 移到各平台 entry point 中注册 |
| `CompatMixinPlugin.java` | `Platform.isModLoaded` | Fabric: `FabricLoader`, NeoForge: `ModList` |
| `ReiCompat.java` | `Platform.isModLoaded` | 同上 |
| `ModNameUtil.java` | `Platform.isModLoaded/getMod` | 同上 |
| `PotionLoader.java` | `ClientLifecycleEvent/LifecycleEvent` | 移到各平台 entry point |
| `BetterRecipeBookClientNeoForge.java` | 全部 Architectury 事件 | 原生 NeoForge 事件 |
| `fabric.mod.json` | `"architectury": ">=19"` | 移除 |
| `neoforge.mods.toml` | `modId = "architectury"` | 移除 |

## Phase 3: Minecraft 26.2 API 变更适配

### 3.1 已知 26.1.2 → 26.2 的潜在变更点

#### 需要调查的领域：
1. **RecipeDisplay 系统** — 配方显示 API 可能变更
2. **GuiGraphics/GuiGraphicsExtractor** — 渲染 API（26.1.2 用 GuiGraphicsExtractor）
3. **RecipeBookComponent** — 配方书组件结构
4. **CreativeModeTab** — 创造模式标签页 API
5. **Mixin 目标** — 类名/方法签名变更
6. **Identifier/ResourceLocation** — 资源标识符统一
7. **网络协议** — 配方同步可能变更
8. **ItemStack/Component 系统** — 物品组件 API

#### 调查方法：
- 使用 `javap` 反编译 26.2 jar 与 26.1.2 对比
- 检查 NeoForge 迁移指南
- 检查 Fabric Loom 映射更新
- 编译错误驱动修复

### 3.2 RBIP 模块适配
- `RecipeBookIsPain.java` 中使用 `ExtendedRecipeBookCategory`
- `ClientRecipeBookMixin.java` 中的 creative tab 逻辑
- 检查 furnace/smoker/blast_furnace 配方分组

## Phase 4: 构建系统调整

### 4.1 选项 A (推荐)：保留 Architectury Loom 仅用于构建
```gradle
// build.gradle
plugins {
    id "dev.architectury.loom" version "1.14.+" apply false  // 只用 loom，不用 API
}
// 不加 architectury-plugin，不加 architectury-fabric/neoforge 依赖
```

### 4.2 选项 B：完全替换为独立构建系统
- Fabric: `fabric-loom` 
- NeoForge: `net.neoforged.moddev` / NeoGradle
- 需要重新配置各子项目的构建脚本

**推荐选项 A**：Architectury Loom 本身只是一个构建工具（处理多平台 mappings），解耦后可以保留。只要不引入 `architectury-fabric`/`architectury-neoforge` API 依赖即可。

## 执行顺序

```
Phase 0 (分支准备) → 15 min
Phase 1 (依赖更新) → 快速修改 gradle.properties
Phase 4 (构建系统) → 用选项 A 保留 loom
Phase 2 (移除 Architectury) → 2-4 小时（逐个替换）
Phase 3 (Minecraft API) → 编译错误驱动，最难预测
Phase 5 (测试) → 持续进行
```
