## 阶段 5 的关键决策：以官方 JEI 26.3 源码为基线，而不是给 26.2 fork 打补丁

先量化了 26.2 fork 与官方 JEI 26.2 的差异：

```
fork 26.2 文件 865 个（api/common/library/gui/fabric）
  834 个与官方逐字节相同
    7 个被 BRBE 改过
   24 个是 BRBE 新增（com/alonie/brbe/jei/**）
  227 个官方文件未收录（neoforge / test / debug / *Test / GUI 运行时等）
```

即 fork = 官方源码 + 很小的一层补丁。因此 26.3 的做法是：

1. 以 `SourceCode/JustEnoughItems-26.3` 为基线，按**同一文件清单**取 26.3 对应文件
   （795 个直接对应；46 个因 JEI 26.3 重组而缺失 —— 26.3 把 CommonApi/FabricApi 合并进
   `Common`，并把 `gui/input`→`common/input`、`gui/GuiProperties`→`common/gui`、
   `common/search.SearchMode`→`common/config`、`network/packets`→`packets/legacy`）
2. 编译错误驱动补齐缺失类（自动闭包脚本，共补 50+ 文件）
3. 重新套用那 7 个 BRBE 改动（`Internal` 无头兜底、去掉 amecs、CycleTicker/CycleTimer 的
   Alt 暂停 + `manualIndexOverride`、键位默认值）
4. 26.3 新增适配：AW 换成官方 JEI 26.3 的 `jei.accesswidener`（新增 Firework*/LootContext，
   删除已消失的 PotionBrewing）；配置系统改为官方新依赖 **mezz_config**；
   若干新抽象方法补齐（`getConfigKeyMappings`、`createRecipeSlotDrawable`×2、
   `createDrawableIngredient(renderer)`、`IRecipeSlotBuilder.setPosition`(区域对齐)、
   `addCraftingStation(type, SlotDisplay)`）；`RecipeMap` 改由配方注册表 lookup 构建

**收益**：834 个未改文件直接就是 26.3 官方版本，不需要逐个文件对着 MC 26.3 打补丁。

## 遗留与降级（26.3）

1. **`ViewerCursor` 自造"抓取拳头"光标失效** —— 26.3 的 MC 从 GLFW 换成 SDL3，不再提供图像光标
   API（只有 `CursorTypes` 标准光标），LWJGL 的 SDL 绑定也未导出 `SDL_CreateColorCursor`。
   已按原有降级路径回退 `CursorTypes.RESIZE_ALL`。恢复需要 `java.lang.foreign` downcall libSDL3。
2. **`BrbeJeiMinecraftMixin` 变空操作** —— 26.3 的 MC 自带 `AtlasManager`，JEI 侧
   `JeiAtlasManager` / `Textures.getAtlasManager()` 均已删除；注入点保留仅为不动 mixin 注册表，
   可随时连同 `mixins.brbe.json` 条目一起清理。
3. **JEI 配置系统多一个内嵌 mod** —— 26.3 起 JEI 的配置由独立 mod `mezz_config` 提供，
   headless-jei 与主 jar 各内嵌一份（避免依赖嵌套 jar 的递归解析）。
4. **dev 运行必须挂 `runtimeOnly`** —— Fabric Loader **不在 dev 下展开 jar-in-jar**，
   否则内嵌 jar 提供的 `BrbeJeiPluginsClientFabric` 入口点会 `ClassNotFoundException` 崩客户端
   （成品 jar 不受影响，走 `fabric.mod.json` 的 `jars`）。
5. 26.3 仍**无 REI**（无 26.3 REI 产物）。
