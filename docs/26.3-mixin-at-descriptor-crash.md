# 26.3 开物品栏崩溃：mixin `@At` 描述符失效（已修复）

**用户反馈**（2026-09-22 12:42）："打开物品栏的时候游戏崩溃"。

## 崩溃现象

```
java.lang.RuntimeException: Mixin transformation of
  net.minecraft.client.gui.screens.recipebook.RecipeButton failed
Caused by: InjectionError: Critical injection failure:
  Callback method brbe$renderPartialOverlay(...)V in
  mixins.brbe-common.json:incompletecrafting.RecipeButtonMixin from mod brbe
  failed injection check, (0/1) succeeded. Scanned 0 target(s).
  at RecipeBookPage.<init> → RecipeBookComponent.<init> → CraftingRecipeBookComponent.<init>
     → InventoryScreen.<init> → Minecraft.handleKeybinds
```

崩在**类加载**：打开物品栏构造 `RecipeBookPage` 时加载 `RecipeButton`，Mixin 应用注入
失败 → `MixinTransformerError` → 游戏崩。

## 根因

`incompletecrafting/RecipeButtonMixin` 的 `@At` 目标描述符仍然写着 **26.2 的渲染管线包**：

```
# 错（26.2）
Lnet/minecraft/client/gui/GuiGraphicsExtractor;blitSprite(Lcom/mojang/blaze3d/pipeline/RenderPipeline;Lnet/minecraft/resources/Identifier;IIII)V
# 对（26.3：管线搬进 renderpearl）
Lnet/minecraft/client/gui/GuiGraphicsExtractor;blitSprite(Lcom/mojang/renderpearl/api/pipeline/RenderPipeline;Lnet/minecraft/resources/Identifier;IIII)V
```

26.3 按类名+描述符匹配调用点，描述符里的 `RenderPipeline` 换了包 → 一个都匹配不上
（"Scanned 0 target(s)"）。**编译期完全看不出来**：注解里的字符串不参与 Java 类型检查。

## 为什么上一轮没抓到

上一轮的静态审计只比对了**方法名**（`method = "extractWidgetRenderState"` 之类）与
**@At 的 owner 类是否存在**，没有比对 `@At` 描述符，也没有看字节码。而主 mod 编译期
（`@At` 是字符串）与本轮 dev 客户端冒烟测试（只到标题界面）都不会加载 `RecipeButton`
——物品栏是进世界后才构造的。

## 修复

`RecipeButtonMixin` 的 `@At` 描述符改为 renderpearl 包（1 行）。

> 顺带纠正一处我自己的误判：审计最初还报了
> `RecipeBookPageAnimationMixin` 的 `RecipeButton;extractRenderState(...)V` 描述符不匹配，
> 我据此改成了 `extractWidgetRenderState` —— **那是错的**。`extractRenderState` 声明在
> `AbstractWidget`（`RecipeButton` 自己只声明 `extractWidgetRenderState`），而
> `RecipeBookPage` 字节码里 `invokevirtual RecipeButton.extractRenderState:(...)V` 一直没变。
> 已回退。教训：`@At` 的 owner 是字节码里的**静态接收者类型**，方法可以声明在父类/接口，
> 判断必须看字节码而不是"目标类有没有这个方法"。

## 验证

1. **新工具** `tools/verify_mixin_targets.py`（根目录，不在 git 管理内）：
   描述符级 + **字节码级**校验所有 mixin 注入点——
   - (a) `method = "name(desc)ret"` 必须在目标类（含父类链与接口链）存在；
   - (b) `@At(target = "Lowner;name(desc)ret")` 指定的调用**必须真的出现在被注入方法的
     字节码里**（以 `javap -c` 的 `// Method ...` 注释为权威）。
   26.3 全部注入点：**0 问题**；对两种回归形态（旧 pipeline 包、错误方法名）**都能报出**。
2. **真实复现验证**：用临时自测 mod（`tools/brbe-screen-selftest/`）在 26.3 实例里
   `--quickPlaySingleplayer` 进世界并自动打开 `InventoryScreen` —— 日志
   `[BRBE-SELFTEST] InventoryScreen opened OK`，无新崩溃报告；
   同一会话 headless JEI 正常索引 1704 条（anvil 834 / brewing 279 / grindstone 210 /
   stonecutting 351 / smithing 30）。

**产物**：`brbe-ava-fabric-26.3-2.3.jar` md5 `6b66f1677b4c6a33b0c190f1cf450d33`，
已原子替换部署到 26.3-Fabric 实例。

## 遗留观察（非本次崩溃）

  **不是 26.3 回归**，Mixin 仅告警且注入成功。要清理可把 accessor 改成 static 方法。
